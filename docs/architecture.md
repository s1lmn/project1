# Архитектура SPORTS MATE

MVP — модульный монолит. React-приложение общается с FastAPI по JSON API. PostgreSQL хранит продуктовые сущности, события и устойчивую очередь уведомлений. Отдельный процесс worker использует ту же кодовую базу и БД.

```text
Telegram WebView → React/Vite → FastAPI → PostgreSQL
                       ↑           ↓
                 Telegram Bot ← worker
```

Критичные бизнес-события и notification jobs записываются в одной транзакции с изменением продукта. Принятие отклика блокирует строку активности через `SELECT FOR UPDATE`, повторно проверяет вместимость и идемпотентно возвращает уже принятое состояние. Уникальные ограничения защищают отклики, оценки и задания от обычных дублей.

Контакт не входит в публичные схемы. Отдельный endpoint каждый раз проверяет принятую пару, статус, блокировки и глобальный запрет. Логи содержат request ID, метод, путь, статус и длительность, но не тела запросов, `initData`, контакты или токены.

## Границы

- Гарантия доставки Telegram — at-least-once с дедупликацией внутри системы; потерянный внешний ответ может привести к редкому повтору.
- Worker использует polling PostgreSQL и `SKIP LOCKED`; Redis для этого масштаба не нужен.
- Метрики доступны только по `X-Internal-Key`. Для публичной эксплуатации рекомендуется закрыть endpoint ещё и сетью/VPN.
- Ограничение частоты запросов хранится в памяти одного API-процесса; при горизонтальном масштабировании его нужно перенести в общий gateway/store.
- Схема начальной миграции создаётся из SQLAlchemy metadata. Любые последующие изменения оформляются отдельной Alembic-ревизией.
